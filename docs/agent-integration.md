# AI エージェント連携の機能案

Issue #13 の検討結果です。機能を 5 つに分け、それぞれ個別の Issue にしました。

## 方針

- エージェントは gh-editor の中のターミナルパネル、または外のターミナルで動きます。どちらでも使えるようにします。
- gh-editor からエージェントへ渡す方法は「ターミナルへ貼り付け」から始めます。特定のエージェントに依存しません。
- エージェントから gh-editor を操作する入口は、Unix ソケットと CLI にします。実行中の gh-editor は環境変数 `GH_EDITOR_SOCKET` でソケットの場所を伝えます。

## 機能一覧

| # | 機能 | 優先度 | 依存 |
|---|------|--------|------|
| A | 現在の文脈をエージェントへ送る | 高 | なし |
| B | 制御用ソケットと `gh-editor` サブコマンド | 高 | なし |
| C | ローカル差分レビューのコメントをエージェントへ返す | 中 | A |
| D | エージェント用スキルの配布 | 中 | B |
| E | エージェントの変更の追従（外部変更の再読み込みと差分表示） | 低 | B |

### A. 現在の文脈をエージェントへ送る

- 選択範囲、ファイルパス、行番号、カーソル位置の診断を `path:行-行` と本文の形式に整えます。
- 送り先はターミナルパネルで動いているプロセスの標準入力です。送る前にプレビューを出し、確認してから貼り付けます。
- コマンドパレットとキーに割り当てます。

### B. 制御用ソケットと CLI

- `gh-editor open <path>[:行]`、`gh-editor diff [path]`、`gh-editor status` を用意します。
- 通信は改行区切りの JSON です。サブコマンドが無い起動は今までどおりです。
- 受け付けるのは同じユーザーのソケットだけです（パーミッション 0600）。

### C. レビューコメントの返送

- 既存の「ローカルの変更のレビュー」のコメントを、Markdown のまま A と同じ経路でエージェントへ送ります。
- 現在は Markdown をクリップボードへコピーする機能のみです。

### D. スキルの配布

- `gh-editor skill install` で、B の CLI の使い方を書いたスキルを `~/.claude/skills/gh-editor/` に書き出します。
- 書き出し先は引数で変えられます。

### E. エージェントの変更の追従

- ディスク上の変更を検知し、開いているバッファへ反映します（未保存の編集があるときは確認します）。
- 変更後に差分レビューを開くショートカットを用意します。

## 決めうちした点

- 最初の送り先はターミナルパネルのみとし、エージェント固有の API は使いません。
- ソケットの場所は環境変数で渡します。固定のパスは使いません。
- 優先順は A → B → C → D → E です。
